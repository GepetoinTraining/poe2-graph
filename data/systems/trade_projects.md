# Trade — Currency Projects

**Status: stub.** 1%-knowledge topic Pedro is donating.

## Scope

**Stacking currency toward a named goal.** A "project" is:

- A specific accomplishment (buy item X, complete craft Y, build alt Z)
- A budgeted cost (this needs Q divines)
- A timeline (by Week N or by event M)
- A definition of done (when complete, the project triggers the next one)

This is the **structural alternative to "saving."** Saving accumulates currency without a target — and currency without a target is dead capital. A project converts saving into directed investment.

Sub-topics to be expanded:
- The project taxonomy: build-completion projects, gearing projects, craft projects, alt-funding projects, league-finale projects
- Project decomposition: a 100-divine project breaks into 10 × 10-divine milestones, each visible
- The project-sequencing decision (what's the next project once this one closes)
- Project budgeting under uncertainty (currency yields vary; project budgets need slack)
- The "premature spend" anti-pattern (using project currency for an unplanned want)
- The "stranded project" anti-pattern (currency stacked for a project the player doesn't actually want anymore)
- League-phase project alignment (some projects only make sense at specific league phases)
- Multi-character / multi-build projects across one league
- Projects as a discipline against currency-velocity edge mis-application (currency in stash IS dead unless it's pre-allocated to a project)
- The "named project" psychological effect (writing the goal down changes the spending behavior)

This is the **highest-leverage trade discipline**. A player who runs a league as a sequence of named projects significantly outperforms one of equivalent farming skill who doesn't.
